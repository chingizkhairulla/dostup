# Личные сообщения сложная

Этот PR заменяет №45 и включает его изменения. Предыдущие миграции не переписывались: новое поведение первого профиля добавлено отдельной миграцией.

## Первый профиль аккаунта

Подсказка «Скачайте приложение, чтобы получать уведомления!» появляется при первом открытии сообщений с первым профилем аккаунта. На втором и последующих профилях её нет, даже если первый профиль ещё не открывал сообщения. Модератор и установленное приложение подсказку не показывают.

Приветствие техподдержки автоматически создаётся после создания первого профиля:

> Здравствуйте, рады вас видеть!
>
> Пишите что можно улучшить или добавить.
>
> Мы с радостью возьмемся за это!

Для продавца сообщение ждёт создания связанного creator_accounts; для покупателя отправляется сразу. Бейдж непрочитанного увеличивается вместе с записью сообщения в одной транзакции. Повторные запросы и создание второго профиля не дублируют приветствие. Удаление первого профиля не делает следующий профиль «первым».

Таблица messenger_account_state имеет первичный ключ auth_user_id. Она сохраняет первый профиль, показ подсказки и доставку приветствия. Таблица и RPC доступны только service_role после проверки сессии в Edge Function. Существующие отметки старой версии мигрируют между профилями одного аккаунта. Старые аккаунты регистрируются без исторической массовой рассылки; автоматическое приветствие предназначено для новых первых профилей. Демопрофили и профили без auth identity исключены.

## Интерфейс

Рамка перетаскивания отображается ниже названия чата/канала, с отступом 12 px со всех сторон и текстом «Отпустите мышку». Это относится и к отдельной карточке техподдержки. Перетаскивание использует прежние загрузку, отмену и лимиты: до 10 файлов, документы/фото до 50 МБ, видео до 500 МБ перед сжатием. В каналы публикует продавец; покупатель сохраняет права чтения.

В создании и редактировании продукта убраны дополнительные кнопки «Свернуть», разделители секций сделаны контрастнее. На телефоне редактор занимает экран целиком и учитывает безопасные отступы устройства. Подпись про отправку ссылки, её пояснение и «Можно вписать несколько» используют 14 px на телефоне и 16 px на компьютере.

## Сохранённые изменения №45

После фактического открытия доступа создаётся один личный чат на пару продавец–покупатель. У продавца покупатели без доступа ко всем его продуктам переходят в «Неактивные». История сохраняется и после удаления продукта, при новом доступе чат возвращается в активные.

Настройка after_access_enabled / after_access_url доступна только продавцу. Требуется абсолютная HTTPS-ссылка без логина/пароля. Приглашение отправляется в существующий чат один раз на выдачу доступа. Подписка ждёт открытого периода. Историческим покупкам миграция восстанавливает только чаты, без отправки приглашений. Подтверждение чтения содержит ID показанных сообщений; скрытый мобильный чат и фоновая вкладка не снимают бейджи.

   - 20261008154130_messages_access_and_onboarding.sql — если ещё не применена из №45;
   - 20261028111154_account_first_profile_messenger_onboarding.sql.
2. Опубликовать Edge Functions manage-products, direct-messages, messenger-state, support-api вместе с изменёнными shared-модулями. Для messenger-state verify_jwt=false: сессии приложения проверяются через resolveCaller.
3. Опубликовать клиент. Один деплой Vercel не применяет SQL и Edge Functions.
4. На staging проверить новый аккаунт: первый профиль получает приветствие и подсказку; второй — нет. Для полного сценария чатов проверить фактическую выдачу доступа, загрузку в Storage/S3 и непрочитанные сообщения.

Автоматические приветствия новых аккаунтов начинаются после применения новой миграции. Миграция не отправляет сообщения существующим аккаунтам. В рамках разработки общая/рабочая база не изменялась.

## Диагностика доставки

Обычный запуск support:welcome показывает только ожидающие доставки новых первых профилей, без сообщений:

```sh
npm run support:welcome
```

При необходимости повторить только эти доставки, задав SUPABASE_URL и SUPABASE_SERVICE_ROLE_KEY в серверной среде:

```sh
npm run support:welcome -- --send
```

Параметр --activate больше не используется. Команда не включает старую массовую кампанию. Повторный запуск безопасен; отчёт содержит sent/skipped/errors.

## Проверки

npm run test:messages выполняет обе миграции и триггеры в изолированном PostgreSQL/PGlite, проверяет первый/второй профиль, параллельные запросы, удаление первого профиля, точный текст, непрочитанные, идемпотентность и закрытые права RPC. Изолированная схема не заменяет staging-проверку Supabase Auth, Storage и S3.

Перед выпуском выполнить штатные Supabase Advisors на staging. Локальный Docker Engine в среде разработки недоступен; миграции исполнялись в PGlite.

Проверка на новом аккаунте из блока «не делать» и будущая настраиваемая авторассылка покупателям в текущую доработку не входят.
