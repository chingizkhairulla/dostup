# Хранилище материалов

## Решение

Единым основным хранилищем материалов выбран AWS S3.

- все новые файлы и обложки загружаются только в S3;
- в `materials.file_url` и `materials.cover_url` сохраняется путь вида `s3://bucket/key`;
- Supabase остаётся базой данных, системой авторизации и местом выполнения Edge Functions;
- Supabase Storage временно поддерживается только для чтения старых материалов.

Так в рабочем продукте нет двух направлений для новых загрузок, а старые ссылки не
ломаются. Размер старых файлов из обоих хранилищ пересчитывает Edge Function
`material-file-sizes`.

## Переход старых файлов

Перенос существующих файлов выполняется отдельно после резервной копии и проверки
числа объектов:

1. выгрузить список старых путей Supabase Storage;
2. скопировать объекты в S3 с проверкой размера и контрольной суммы;
3. обновить `materials.file_url` только для успешно проверенных копий;
4. выдержать период наблюдения;
5. удалить старые объекты только отдельным явно подтверждённым действием.

Текущая миграция базы ничего не удаляет и не переписывает существующие пути.
