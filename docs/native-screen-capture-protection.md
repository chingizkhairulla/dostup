# Нативная защита раздела «Материалы»

Веб-приложение/PWA не может узнать о системном скриншоте или записи экрана и
не может гарантированно скрыть содержимое от ОС. Клиентская часть поэтому не
имитирует такую защиту через JavaScript. Реальная защита включается в нативных
оболочках Capacitor из каталогов `android/` и `ios/`.

Мобильные оболочки собирают тот же Vite-фронтенд и обращаются к уже настроенному
Supabase. Дополнительный backend, база данных или сервер для защиты не нужны.

## Контракт bridge

Фронтенд подключается к локальному Capacitor-плагину `ScreenProtection`:

```ts
ScreenProtection.setProtected({ enabled: boolean });
ScreenProtection.isCaptured(); // { isCaptured: boolean }
ScreenProtection.addListener("screenCaptureChanged", listener);
```

- `setProtected({ enabled: true })` вызывается при входе покупателя в раздел
  «Материалы»;
- `setProtected({ enabled: false })` вызывается при выходе из раздела;
- `isCaptured()` вызывается при входе и каждом возвращении приложения из фона;
- при изменении состояния записи плагин отправляет событие
  `screenCaptureChanged`.

При `isCaptured: true` React полностью размонтирует материалы и показывает
непрозрачный чёрный экран. При `false` содержимое возвращается автоматически.

## Android

Плагин добавляет `WindowManager.LayoutParams.FLAG_SECURE` к окну WebView и
удаляет флаг после выхода из раздела. Android возвращает чёрный/пустой кадр для
скриншота, записи и превью в переключателе приложений.

На Android 15+ плагин также использует системный callback записи экрана и
передаёт его состояние в React. На Android 14 и ниже ОС не предоставляет
надёжного API обнаружения записи, но `FLAG_SECURE` всё равно блокирует кадр.

## iOS

Плагин возвращает `UIScreen.main.isCaptured`, слушает
`UIScreen.capturedDidChangeNotification` и отправляет состояние в React. При
активной записи React размонтирует материалы и показывает блокирующий экран с
сообщением. При уходе приложения в фон поверх WebView создаётся отдельный
нативный непрозрачный чёрный экран, чтобы скрыть системный snapshot.

iOS не позволяет гарантированно запретить сам факт создания скриншота. Событие
`UIApplication.userDidTakeScreenshotNotification` приходит уже после снимка;
его можно использовать для аудита или уведомления, но не как обещание
блокировки.

## Ограничения

- В обычном браузере и установленной PWA системная защита недоступна.
- Съёмку экрана другим физическим устройством предотвратить невозможно.
- Скачанный или открытый во внешнем приложении файл находится вне защищённого
  экрана Dostup. Право скачивания остаётся отдельной настройкой материала.

## Сборка и проверка

```bash
npm ci
cp .env.example .env # заполнить публичные VITE_/NEXT_PUBLIC_ параметры Supabase
npm run native:sync
```

- Android: открыть `android/` в Android Studio или выполнить
  `./android/gradlew -p android assembleDebug` при настроенных Java 21 и Android
  SDK 36.
- iOS: открыть `ios/App/App.xcodeproj` в Xcode 26+ на macOS.
- Обязательная ручная приёмка выполняется на физических Android/iOS-устройствах
  со включённой системной записью экрана.
